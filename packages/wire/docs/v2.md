# Schema v2 — package 0.2.0 source contract

**Status:** source implementation; build, package artifacts, verification and
consumer migrations are pending. No endpoint or migrated browser support is
claimed. V2 does not enable a runtime or activate a canonical transport gate.

## APIs and version selection

Explicit root exports: `AgentEventEnvelopeV2`, `AgentAcceptedEnvelopeV2`,
`AgentLiveEnvelopeV2`, `AgentChangeV2`, `AgentChangePayloadsV2`,
`AGENT_CHANGE_TYPES_V2`, `AGENT_LIVE_CHANGE_TYPES_V2`,
`parseAgentEventEnvelopeV2`, and native configure types/`parseAgentConfigureResultV2`.
Other exported v2 payload types describe queue, branch, rotation, compaction,
model/configuration and request evidence. V1 exports still mean v1.

Both new parsers accept an optional expectedSessionId and reject any other
schemaVersion. No parser auto-upgrades/downgrades or retries an older transport.
Applications must explicitly negotiate v2 before sending it; `agent-wire-v2` is
the proposed transport format label, not an implemented endpoint negotiation.

## One accepted boundary, one cursor

```ts
import { parseAgentEventEnvelopeV2 } from '@qduc/agent-wire';
const boundary = parseAgentEventEnvelopeV2({
  schemaVersion: 2, kind: 'accepted', sessionId: 'session-1',
  seq: 43, occurredAt: '2026-10-03T00:00:00Z',
  changes: [
    { type: 'queue_changed', payload: {
      change: { type: 'queue_discarded', messageIds: ['message-a', 'message-b'] },
    } },
  ],
});
```

The example values illustrate a shape; real producers MUST copy the actual
accepted writer boundary, not generate values like these for an existing event.
Exactly schemaVersion/kind/sessionId/seq/occurredAt/changes are allowed.
`seq` is a positive safe integer, copied from the accepted Session sequence;
`occurredAt` is its original accepted at, nonempty without control characters.
The parser deliberately does not parse/reformat the time or prove its origin.
Session IDs in v2 are nonempty/control-free real binding identities, without a
new v1-style regex/length restriction imposed on native identity.

`changes` is an ordered array. All changes derive from that SAME accepted
boundary, and the whole array is one atomic consumer transaction. It can be
empty for a boundary with no public changes. It can contain several
command_message or subagent_command_message entries from one tool_finished.
There is no sub-event numeric ID or timestamp. The SSE frame has one id=seq.
Do not group different accepted seq/at pairs into one envelope or split a batch
into frames that reuse or invent cursors.

Sequences may be sparse: facts with no public changes may be folded rather than
published. Require increasing cursors, not seq==previous+1. A consumer commits a
cursor only after ALL changes are applied atomically. Ignore an already
committed whole boundary, never individual same-ID changes. On partial failure,
keep the old cursor/view and reload or replay the whole boundary. Persisted
checkpoint/view and cursor must describe the same cut. Sequence numbers are not
publication positions, clocks or a transport-generated journal.

## Live envelopes and replay parity

```ts
parseAgentEventEnvelopeV2({
  schemaVersion: 2, kind: 'live', sessionId: 'session-1',
  changes: [{ type: 'reasoning_delta', payload: { delta: 'Considering options' } }],
});
```

Exactly schemaVersion/kind/sessionId/changes are allowed. Changes must be
nonempty and use `AGENT_LIVE_CHANGE_TYPES_V2`: reasoning_delta, tool_progress,
tool_call_streaming_delta, task_progress, automatic_memory_notice, retry,
retry_exhausted. Live envelopes have NO seq, id, occurredAt, or SSE id, and never
advance replay position. They make no replay, restart-retention or deduplication
promise; order is only the actual live publication order on the connection.
Current native producers lack accepted metadata for these transient updates.

A future native accepted fact can use the same change type inside an accepted
envelope, but only when genuinely accepted by its sole writer. Live availability
is NOT old durable-stream replay parity. Product-visible information requiring
replay must gain real native acceptance before parity can be claimed. Neither a
server replay journal nor invented timestamps nor silent omission is allowed.
The package contains no writer, journal, recovery routine or cursor generator.

## Changes, ownership and payload validation

A change is exactly `{type,payload,branch?}`. Root changes omit branch. If known
from the accepted branch owner, branch is exactly
`{branchId,taskId,turnId,parentTurnId?,rootTurnId?}`. All present identities must
be nonempty/control-free. Missing ancestry stays absent. A provider/model/call
ID is not a Session/branch/turn identity. The actual owning turn remains in
payloads that name it; compaction/history ownership must match the branch turn.
Some inherited subagent payloads name a parent turn: do not rewrite that field
to the child's turn just to match the wrapper. No child-to-root promotion.

The closed change vocabulary includes all v1 event names plus queue_changed,
session_rotated, reasoning, tool_progress, tool_call_streaming_delta,
task_progress, automatic_memory_notice, command_started, command_finished,
history_replaced, configuration. Unknown change types/keys reject.

Envelope validation checks each payload is an object. Queue discriminants and
affected IDs, rotation, compaction and optional history correlation receive the
additional checks below. Other payloads, queue submission record internals and
additional public queue read-model fields remain application-validated. This is
not a claim of full event-specific validation. Applications still own safe
public projection/redaction, authentication, authorization and provenance.
Parsers retain the original v2 value; callers must treat it as immutable.

### Aggregate queue

queue_changed.payload contains `change:AgentQueueChangeV2` plus any actual public
queue projection fields. The change vocabulary matches native public changes:
queue_submitted{record}, queue_edited{messageId,content}, queue_retracted{messageId},
queue_discarded{messageIds}, queue_started{messageId,turnId},
queue_steered{messageIds,turnId},
queue_cancelling{turnId,cancelledMessageIds,retainedMessageIds},
queue_settled{turnId,outcome,preservePendingSteers?}, queue_resumed{}, queue_recovered{}.
Each includes its `type`; changes themselves have exact keys. IDs remain in
original array order, unique within an array; cancellation sets are disjoint.
Empty affected arrays stay empty. No per-reservation rejection envelope, inferred
terminal or generated ID is substituted. Submitted record/content deep schemas
and read-model fields are the native/public application owner's responsibility.

### Rotation/reset

session_rotated.payload is exactly the actual native public rotation:
`{logicalSessionId,backingSessionId,predecessor:{sessionId,throughSeq},commandId,
configuration:{model,reasoning?,temperature?},handoff?:{clientRequestId,messageId,turnId}}`.
Logical identity must equal the envelope Session; predecessor throughSeq is a
nonnegative safe integer. It is session-scoped, never a branch change.

The consumer keeps logical Session identity, uses the accepted new backing
identity, and clears rotated root provider/foreground context according to the
native boundary, or reloads an actual accepted projection cut. Preserved tasks,
queue, goals, notifications and request costs are NOT all reset. No synthetic
session_created, terminal or generic clear-everything reset event is added.
Compacted/unavailable cursor handling must reload a real accepted snapshot and
its actual resume cut, not give an arbitrary latest view an earlier cursor.
The package does not define an application snapshot DTO or construct a reload.

### Compaction

V2 context_compaction_started/completed/failed carry the respective native
attempt fact payload minus `type`, including its actual turnId/compactionId.
They are NOT v1 guessed start/end metrics. Shapes are exported:
AgentCompactionStartV2 / AgentCompactionCompleteV2 / AgentCompactionFailedV2.

Start requires trigger manual|automatic, ModelRef{provider,model}, and before
estimate; strategy native|local, contextWindow, maxRequestInputTokens (nullable),
lastCompletedInputTokens are optional. Estimates have exactly
renderedInputTokens/outputReserveTokens/safetyReserveTokens/hardFitTokens.
Completion has actual strategy, after estimate, durationMs and requests. Failure
has durationMs/requests and the exact native blocked/interrupted/cancelled/failed
union in AgentCompactionFailureV2, with ModelError when failed. Duration and
estimates are finite nonnegative numbers; duration can be fractional. Never
subtract wall-clock envelope times to make duration.

Requests are real physical references: requestId/modelStep/model/outcome and
optional usage{inputTokens,outputTokens,cachedInputTokens}/costUsd. Request IDs
are unique in the array; step is a nonnegative safe integer. Costs can be finite
nonnegative numbers or numeric strings, retained unchanged. [] stays known empty;
absent usage/cost/strategy stays absent, zero stays zero, nullable limits stay
null. Estimates are not measured usage; request references are not extra charges.
Failed/cancelled requests need not have model_response_completed receipts.

Native producer/replay, not this stateless parser, enforces one start and at most
one outcome per attempt in its owning scope; completion follows its matching
accepted history_replaced.compactionId. That optional field, when public, must
name a real owning turn and compaction reason. Preserve starts or accepted
replacements with unobserved outcome after a crash; never synthesize failure,
end time, request evidence or completion. A cancelled surrounding turn does not
retract an accepted compaction completion. No history/rearm/accounting update is
caused by lifecycle evidence alone.

## Native configure receipt response

`parseAgentConfigureResultV2(value, expectedSessionId?)` accepts exactly
`{schemaVersion:2,sessionId,result:<AgentConfigureCommandResultV2>}`.
It is a configure-only native command result, not a configuration discovery DTO:

- ok:true,kind:command_pending,receipt,outcome absent → HTTP202, not installation.
- ok:true,kind:command_finished,receipt.outcome.kind:configured → HTTP200 with
  original accepted concrete configuration, not current state from a later run.
- ok:false,code:command_rejected or command_interrupted,commandId,message,receipt
  → native typed negative/interrupted HTTP mapping (normally409 or503), not
  invented success. receipt outcome must match its code and command identity.
- Nonreceipt native errors retain ok:false/code/message/optional commandId and
  have no fabricated receipt or replay provenance. HTTP errors before native
  dispatch keep their authorized safe error contract; do not fabricate a native
  result merely to put them inside this wrapper.

Receipt is exactly `{request,revision,outcome?}`. Request retains the original
commandId, operation{kind:'configure',configuration}, optional admission:'idle'
and expectedRevision. Selection may name model, concrete/default reasoning,
temperature and profileId; the accepted configured output requires concrete
model and has only optional concrete reasoning/temperature. Requested profileId
is NOT accepted profile metadata. Original receipt revision is the admission
revision, not an invented post-install revision. `replayed?` remains absent when
unknown and preserves recorded false/true; parsing never inserts it.

The HTTP caller retains a real stable invocation key, original expectedRevision
and identical patch/preconditions on retry; the native writer owns same-key
lookup/conflict and atomic idle/stale admission before work. HTTP validation,
mode/default/profile preparation and safe diagnostic redaction remain application
owned. Read-only discovery is separate current installed state and real current
revision. Do not project a later discovery as an earlier successful mutation or
silently poll/promise completion on a pending receipt.
