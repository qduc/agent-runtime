# Schema v2 — package 0.2.1 source contract

**Status:** source contract. A local package build or parser check does not
establish consumer runtime or browser acceptance. No endpoint or migrated browser
support is claimed. V2 does not enable a runtime or activate a canonical transport
gate.

## APIs and version selection

Explicit root exports: `AgentEventEnvelopeV2`, `AgentAcceptedEnvelopeV2`,
`AgentLiveEnvelopeV2`, `AgentChangeV2`, `AgentChangePayloadsV2`,
`AGENT_CHANGE_TYPES_V2`, `AGENT_LIVE_CHANGE_TYPES_V2`,
`parseAgentEventEnvelopeV2`, and native configure types/`parseAgentConfigureResultV2`.
Other exported v2 payload types describe queue, branch, rotation, compaction,
model/configuration and request evidence. V1 exports still mean v1.

`AgentAcceptedChangeTypeV2` is the accepted allowlist's type;
`AgentLiveChangeTypeV2` is the live allowlist's type. `AgentChangeTypeV2` is their
union, and `AgentChangeV2`/`AgentChangePayloadsV2` represent either kind. The
accepted envelope's changes are narrowed to
`Extract<AgentChangeV2,{type:AgentAcceptedChangeTypeV2}>`; the live envelope uses
its live equivalent. Thus a general change can be a live error without error
being assignable to an accepted envelope. Select/narrow by envelope kind, not
just a general change type. Runtime parsing independently uses the matching
allowlist and rejects accepted error.

Both new parsers accept an optional expectedSessionId and reject any other
schemaVersion. No parser auto-upgrades/downgrades or retries an older transport.
Applications must explicitly negotiate v2 before sending it; `agent-wire-v2` is
the proposed transport format label, not an implemented endpoint negotiation.

## One accepted boundary, one cursor

```ts
import { parseAgentEventEnvelopeV2 } from '@qduc/agent-wire';
const boundary = parseAgentEventEnvelopeV2({
  schemaVersion: 2, kind: 'accepted', sessionId: 'session-1',
  seq: 43, occurredAt: '2026-10-03T00:00:00Z',
  changes: [
    { type: 'queue_changed', payload: {
      change: { type: 'queue_discarded', messageIds: ['message-a', 'message-b'] },
    } },
  ],
});
```

The example values illustrate a shape; real producers MUST copy the actual
accepted writer boundary, not generate values like these for an existing event.
Exactly schemaVersion/kind/sessionId/seq/occurredAt/changes are allowed.
`seq` is a positive safe integer, copied from the accepted Session sequence;
`occurredAt` is its original accepted at, nonempty without control characters.
The parser deliberately does not parse/reformat the time or prove its origin.
Session IDs in v2 are nonempty/control-free real binding identities, without a
new v1-style regex/length restriction imposed on native identity.

`changes` is an ordered array. All changes derive from that SAME accepted
boundary, and the whole array is one atomic consumer transaction. It can be
empty for a boundary with no public changes. It can contain several
command_message or subagent_command_message entries from one tool_finished.
There is no sub-event numeric ID or timestamp. The SSE frame has one id=seq.
Do not group different accepted seq/at pairs into one envelope or split a batch
into frames that reuse or invent cursors.

Sequences may be sparse: facts with no public changes may be folded rather than
published. Require increasing cursors, not seq==previous+1. A consumer commits a
cursor only after ALL changes are applied atomically. Ignore an already
committed whole boundary, never individual same-ID changes. On partial failure,
keep the old cursor/view and reload or replay the whole boundary. Persisted
checkpoint/view and cursor must describe the same cut. Sequence numbers are not
publication positions, clocks or a transport-generated journal.

## Live envelopes and replay parity

```ts
parseAgentEventEnvelopeV2({
  schemaVersion: 2, kind: 'live', sessionId: 'session-1',
  changes: [{ type: 'reasoning_delta', payload: { delta: 'Considering options' } }],
});
```

Exactly schemaVersion/kind/sessionId/changes are allowed. Changes must be
nonempty and use `AGENT_LIVE_CHANGE_TYPES_V2`: reasoning_delta, tool_progress,
tool_call_streaming_delta, task_progress, automatic_memory_notice, retry,
retry_exhausted, error, turn_failed. Live envelopes have NO seq, id, occurredAt,
or SSE id, and never advance replay position. They make no replay, restart-retention or deduplication
promise; order is only the actual live publication order on the connection.

### Explicit raw-stream replay exception (option B)

The user chose option B (Discord message `1566281061087059989`): raw reasoning
chunks and intermediate tool-progress updates remain live-only, including after
reconnect or crash. Accepted reasoning summaries and final tool results, when
actually accepted by the native writer, are the recovery surface. An interrupted
live prefix can be lost; neither replay nor hydration promises to restore it.
This is an explicit raw-stream replay parity exception, NOT full replay parity.
It applies to raw root/branch/task presentation streams, not just the root UI.

Do not persist transient prefixes, promote raw chunks into accepted facts,
reconstruct missing text from summaries/results, or fabricate cursors,
timestamps or history. A structural accepted change name is not permission to
change this retention policy. Other accepted public evidence keeps its actual
native boundary and recovery semantics; live availability alone is not durable
replay. The package contains no writer, journal, recovery routine or cursor
generator.

This presentation policy does NOT authorize stripping provider-native history.
Preserve complete provider-required reasoning items, signatures, encrypted
metadata, tool calls and tool results, unchanged as required for continuation.
UI raw deltas are not a substitute for those complete native items; a public
summary alone does not establish provider continuation. After all M6
implementation, verify actual provider continuation, including tool-result
round trips and supported reconnect/crash recovery, through the real provider
path. Until that authorized verification runs, no provider-continuity acceptance
is claimed.

Server and browser user-facing contracts must disclose that raw reasoning and
intermediate progress are visible live but may be unavailable after reconnect
or crash; recovery uses accepted summaries and final results rather than the
original raw stream. They must not label this full raw-stream replay parity.

## Changes, ownership and payload validation

A change is exactly `{type,payload,branch?}`. Root changes omit branch. If known
from the accepted branch owner, branch is exactly
`{branchId,taskId,turnId,parentTurnId?,rootTurnId?}`. All present identities must
be nonempty/control-free. Missing ancestry stays absent. A provider/model/call
ID is not a Session/branch/turn identity. The actual owning turn remains in
payloads that name it; compaction/history ownership must match the branch turn.
Some inherited subagent payloads name a parent turn: do not rewrite that field
to the child's turn just to match the wrapper. No child-to-root promotion.

The closed change vocabulary includes all v1 event names plus queue_changed,
session_rotated, reasoning, tool_progress, tool_call_streaming_delta,
task_progress, automatic_memory_notice, command_started, command_finished,
history_replaced, configuration, cost, request_cost_recorded, goal, goal_proposed,
verification, notice, background_notice_enqueued, background_notices_delivered,
message, task_changed, tool_called. This is the accepted allowlist; error is
live-only and is deliberately NOT in it. Unknown change types/keys reject.

Envelope validation checks each payload is an object. Tool-call/live-error and
message/task descriptors, queue discriminants and affected IDs, rotation,
compaction and optional history correlation receive the additional checks below.
Other payloads, message/tool content parts, task origin/error internals, queue
submission record internals and
additional public queue read-model fields remain application-validated. This is
not a claim of full event-specific validation. Applications still own safe
public projection/redaction, authentication, authorization and provenance.
Parsers retain the original v2 value; callers must treat it as immutable.

### Accepted messages and task descriptors

`message` and `task_changed` are accepted-only additions to the same
still-unreleased package0.2.0/schema2 contract, never live changes. They retain
actual native public payloads after hydration as well as during replay; shared
source support does not prove the artifact/server/browser path is installed or
verified. Neither is a terminal/status event or a provider-history container.
Hydration covers a cut, not subsequent accepted updates: producer, adapter and
consumer vocabulary must agree end to end. An unmapped real message/task fact
must not be silently treated as a boundary with no public changes.

`message.payload` is exactly `{message,replacesDraftId?}`. Its public message
object requires `id`, `role` (user|assistant|tool), array `content` and string
`text`. Only the native optional `turnId`, `modelStep`, `executionId`, `isError`,
`draft`, `replacesDraftId` fields are allowed. IDs are nonempty/control-free;
modelStep is a nonnegative safe integer and the flags are booleans. Content part
schemas and safe public projection remain application-owned; no provider-native
history or private reasoning field is added. Empty content/text and recorded
false/zero stay intact, with absent optional fields still absent.

Root messages omit branch; child messages retain the actual accepted branch
wrapper. Do not infer a turn or branch from role/model/content. Preserve both
recorded draft-replacement fields where present; the browser replaces the named
draft in place rather than appending a synthetic assistant turn. Do not infer a
replacement relation when the native payload omits it.

`task_changed.payload` is exactly `{change,at,task}`. Change is one of
`task_started|task_backgrounded|task_stop_requested|task_finished|task_question_opened|task_question_closed`; at is the
native finite nonnegative numeric task time, not an envelope clock/cursor.
The task requires only actual `id` and status
`running|awaiting_interaction|cancelling|completed|cancelled|failed|interrupted`.
Its allowed optional public fields are turnId/sessionId/parentExecutionId/
sourceCallId/origin/agentId/kind/label/input/name/role/model/mode/startedAt/
lastActivityAt/completedAt/text/progress/result/pendingQuestion. IDs, string fields, native
kind(shell|subagent), mode(foreground|background), model and finite nonnegative
times are validated when present, not filled in. Task metadata is root-scoped;
the parser rejects an extra branch wrapper. A parent turnId does not assert
that the foreground still runs, and no branch identity is manufactured.

A present pendingQuestion is exactly `{messageId,question}`: messageId is a
nonempty identity and question is nonblank text. It represents a child asking
the orchestrator, not a user interaction. Preserve native question open/close
change names: the opened task snapshot carries the question and closing removes
it. Applications own accepted lifecycle ordering, answer delivery and replay;
this stateless parser does not infer a question or answer from task status.

A present result requires native kind completed|cancelled|failed|interrupted
and permits only optional output/toolUseCounts/error/reason. Output/reason are
strings; error and origin internals remain application-validated objects.
Counts live at **task.result.toolUseCounts**, not task.toolUseCounts. Each entry
is exactly `{toolName,count}` with a nonempty string tool name and positive
safe integer count, unique by name. Absent counts mean unknown; [] means known
empty. Preserve empty strings, optional result fields and actual recorded task
evidence without coercion or inferred completion. A stop request remains
cancelling; a child turn terminal is not task completion. Consumers must apply
the descriptor in the same atomic accepted batch, not relabel it as a terminal.

`status_changed` remains excluded: the aligned native source has no accepted
producer for it. The separate accepted audit/budget events
`model_response_completed` and `budget_observed` remain excluded pending an
actual client contract; they are not relabelled as cost, notice or terminal.
Tool-call and transient-error/failure contracts are below. Option B's raw-stream
replay exception and provider-native-history preservation remain unchanged.

### Accepted tool calls and live runtime failures

`tool_called` is accepted-only. Payload is exactly `{tool}`, with required
executionId/turnId/toolName/input/status. Execution and turn IDs are
nonempty/control-free, toolName is a nonempty string, input is a public JSON
value (including actual null/scalar/array values), and status must be `called`.
Only native optional parentExecutionId/callId/output/isError/progress/display/
content fields are allowed. Optional IDs, strings/boolean, JSON display and
array content receive structural checks; content part schemas and safe public
projection remain application-owned. No output/result is required or inferred.
Optional absence, empty output/content, false and zero remain recorded values.

Retain the actual accepted branch wrapper when supplied; root calls omit it.
A called tool may never physically start. Consumers create/update the tool entry
by real execution identity/input and later update that same entry on tool_started,
not infer a physical start or create a duplicate from a guessed call ID. A
result without a known call remains unmatched, not assigned an invented name.
Public tool input/content is not provider-native history.

`error` is **live-only**, never an accepted change. Payload is exactly
`{error:{kind,message,retryable?,retryAfterMs?}}`: kind/message are strings,
retryable is a boolean when present, and retryAfterMs is a finite nonnegative
number when present. Preserve false/zero and absent fields. Both the accepted
change type and parser exclude error; placing it in a general change union does
not authorize a durable error. Live frames have no seq/time/SSE ID or checkpoint.
Browser errors remain connection-local visible evidence: do not mutate durable
status/terminal, emit a synthetic accepted notice/result, or persist replayable
history from the error alone.

The native synchronize path separately emits a real null-seq failed turn end.
Its server mapping is a **live `turn_failed`**, retaining actual turnId,
outcome:'failed', failure reason and optional recorded finalText/cause fields.
It may accompany the live error. The existing accepted turn_failed name/behavior
is unchanged; envelope kind distinguishes the two. The shared parser retains
this inherited terminal payload as an application-validated object, not a new
strict terminal schema. A live failure may settle the active turn's visible
running/error overlay, but cannot advance an accepted cursor, create a durable
terminal/history/result or claim accepted journal evidence. Hydration/current
accepted state remains authoritative after the connection. If the kind
boundary is lost, fail closed rather than promote live failure into durability.
No status_changed producer/event, synthetic cursor or snapshot event is added.

These complete the same unreleased0.2.0/schema2 source contract, not artifact or
consumer acceptance. Provider-native reasoning/signatures/encrypted metadata/
tool calls/results remain intact; actual continuation verification stays deferred
until all M6 implementation is complete.

### Accepted cost, goals and notices

These eight names are accepted-only, never live changes. They complete the
still-unreleased package0.2.0/schema2 vocabulary; this is not a new package
release or schema negotiation. Payloads retain the exact native public object:

| Change | Public payload |
| --- | --- |
| cost | `{totalUsd,currency:'USD'}` |
| request_cost_recorded | `{turnId,rootTurnId,parentTurnId?,record}` |
| goal | `{goal:<native public goal|null>,generation?}` |
| goal_proposed | `{goal:<native public goal>}` |
| verification | `{verification:<native public verification|null>}` |
| notice | `{kind,message}` |
| background_notice_enqueued | `{notice:{id,kind,taskIds,text}}` |
| background_notices_delivered | `{clientRequestId,turnId,notificationIds}` |

The shared parser checks these payloads are objects, not their domain schemas.
Native/application owners retain pricing, goal and notice validation and public
redaction. Nulls, empty arrays, omitted optional fields and recorded zeros stay
as recorded; no metric, currency, identity or time default is inserted.

`cost` replaces authoritative root aggregate state; it is NOT an increment.
`request_cost_recorded` upserts the complete physical receipt by its actual
`record.requestId`, including outcome, optional measured evidence, signed
accounting values and immutable native ownership. Later evidence can enrich or
correct that same request, not add another charge. Neither change may have a
`branch` wrapper (the parser rejects one), even within a subagent boundary:
request payload ancestry already identifies the physical producing turn.
Other branch changes retain actual accepted branch identity when applicable.
Branch hydration request records are views of those same physical receipts,
not additional charges. Never add aggregate cost to request records, re-charge
compaction references, or derive usage/prices from estimates.

The aligned native base's accepted projection does not emit aggregate `cost`.
The name permits a real event if supplied; it does not authorize manufacturing
an aggregate from request records, response cost or hydration. Unavailable
native aggregate cost remains unavailable.

Goals/verification are native public state/evidence, not inferred human success.
A goal proposal is not an active goal; accepted null goal/verification values
retain their clearing meaning. Public notices are not private memory content.
Notification IDs and delivery ownership remain exact; a background delivery's
turnId names the actual silent turn, not a newly created foreground turn.
Preserve accepted order and the envelope's actual Session/seq/at boundary.

Adding vocabulary does not implement a producer, server mapping, consumer
reduction or hydration. Servers must explicitly retain these raw public changes
in accepted batches; browsers must apply them atomically and hydrate only real
native snapshot state. Hydration is separate from this SSE envelope and cannot
fabricate missing cost, historical notices/goals or branch history. Raw
reasoning/progress follow the explicit live-only exception above, not a pending
raw-stream persistence requirement. Artifact intake, consumer migration,
provider-continuation verification and both runtime gates remain pending.

### Aggregate queue

queue_changed.payload contains `change:AgentQueueChangeV2` plus any actual public
queue projection fields. The change vocabulary matches native public changes:
queue_submitted{record}, queue_edited{messageId,content}, queue_retracted{messageId},
queue_discarded{messageIds}, queue_started{messageId,turnId},
queue_steered{messageIds,turnId},
queue_cancelling{turnId,cancelledMessageIds,retainedMessageIds},
queue_settled{turnId,outcome,preservePendingSteers?}, queue_resumed{}, queue_recovered{}.
Each includes its `type`; changes themselves have exact keys. IDs remain in
original array order, unique within an array; cancellation sets are disjoint.
Empty affected arrays stay empty. No per-reservation rejection envelope, inferred
terminal or generated ID is substituted. A submitted record retains the flat public
`clientRequestId` and `messageId` identities and its object-valued `admission`;
there is no synthetic `request` wrapper. Public projection flattens the durable
record; validators must follow that public shape, not storage internals.
Submitted record/content deep schemas
and read-model fields are the native/public application owner's responsibility.

### Rotation/reset

session_rotated.payload is exactly the actual native public rotation:
`{logicalSessionId,backingSessionId,predecessor:{sessionId,throughSeq},commandId,
configuration:{model,reasoning?,temperature?},handoff?:{clientRequestId,messageId,turnId}}`.
Logical identity must equal the envelope Session; predecessor throughSeq is a
nonnegative safe integer. It is session-scoped, never a branch change.

The consumer keeps logical Session identity, uses the accepted new backing
identity, and clears rotated root provider/foreground context according to the
native boundary, or reloads an actual accepted projection cut. Preserved tasks,
queue, goals, notifications and request costs are NOT all reset. No synthetic
session_created, terminal or generic clear-everything reset event is added.
Compacted/unavailable cursor handling must reload a real accepted snapshot and
its actual resume cut, not give an arbitrary latest view an earlier cursor.
The package does not define an application snapshot DTO or construct a reload.

### Compaction

V2 context_compaction_started/completed/failed carry the respective native
attempt fact payload minus `type`, including its actual turnId/compactionId.
They are NOT v1 guessed start/end metrics. Shapes are exported:
AgentCompactionStartV2 / AgentCompactionCompleteV2 / AgentCompactionFailedV2.

Start requires trigger manual|automatic, ModelRef{provider,model}, and before
estimate; strategy native|local, contextWindow, maxRequestInputTokens (nullable),
lastCompletedInputTokens are optional. Estimates have exactly
renderedInputTokens/outputReserveTokens/safetyReserveTokens/hardFitTokens.
Completion has actual strategy, after estimate, durationMs and requests. Failure
has durationMs/requests and the exact native blocked/interrupted/cancelled/failed
union in AgentCompactionFailureV2, with ModelError when failed. Duration and
estimates are finite nonnegative numbers; duration can be fractional. Never
subtract wall-clock envelope times to make duration.

Requests are real physical references: requestId/modelStep/model/outcome and
optional usage{inputTokens,outputTokens,cachedInputTokens}/costUsd. Request IDs
are unique in the array; step is a nonnegative safe integer. Costs can be finite
nonnegative numbers or numeric strings, retained unchanged. [] stays known empty;
absent usage/cost/strategy stays absent, zero stays zero, nullable limits stay
null. Estimates are not measured usage; request references are not extra charges.
Failed/cancelled requests need not have model_response_completed receipts.

Native producer/replay, not this stateless parser, enforces one start and at most
one outcome per attempt in its owning scope; completion follows its matching
accepted history_replaced.compactionId. That optional field, when public, must
name a real owning turn and compaction reason. Preserve starts or accepted
replacements with unobserved outcome after a crash; never synthesize failure,
end time, request evidence or completion. A cancelled surrounding turn does not
retract an accepted compaction completion. No history/rearm/accounting update is
caused by lifecycle evidence alone.

## Native configure receipt response

`parseAgentConfigureResultV2(value, expectedSessionId?)` accepts exactly
`{schemaVersion:2,sessionId,result:<AgentConfigureCommandResultV2>}`.
It is a configure-only native command result, not a configuration discovery DTO:

- ok:true,kind:command_pending,receipt,outcome absent → HTTP202, not installation.
- ok:true,kind:command_finished,receipt.outcome.kind:configured → HTTP200 with
  original accepted concrete configuration, not current state from a later run.
- ok:false,code:command_rejected or command_interrupted,commandId,message,receipt
  → native typed negative/interrupted HTTP mapping (normally409 or503), not
  invented success. receipt outcome must match its code and command identity.
- Nonreceipt native errors retain ok:false/code/message/optional commandId and
  have no fabricated receipt or replay provenance. HTTP errors before native
  dispatch keep their authorized safe error contract; do not fabricate a native
  result merely to put them inside this wrapper.

Receipt is exactly `{request,revision,outcome?}`. Request retains the original
commandId, operation{kind:'configure',configuration}, optional admission:'idle'
and expectedRevision. Selection may name model, concrete/default reasoning,
temperature and profileId; the accepted configured output requires concrete
model and has only optional concrete reasoning/temperature. Requested profileId
is NOT accepted profile metadata. Original receipt revision is the admission
revision, not an invented post-install revision. `replayed?` remains absent when
unknown and preserves recorded false/true; parsing never inserts it.

The HTTP caller retains a real stable invocation key, original expectedRevision
and identical patch/preconditions on retry; the native writer owns same-key
lookup/conflict and atomic idle/stale admission before work. HTTP validation,
mode/default/profile preparation and safe diagnostic redaction remain application
owned. Read-only discovery is separate current installed state and real current
revision. Do not project a later discovery as an earlier successful mutation or
silently poll/promise completion on a pending receipt.

See [migration](migration-v1-v2.md) for packaging/consumer boundaries and rollback.

Task lifecycle descriptors retain optional native tool tracking: `lastToolName`,
`lastTool: { label, state: running|success|failed }`, and `toolCounts` with unique
nonempty tool names and positive safe integer counts. A question opened while a
child tool runs retains these fields; consumers must not discard them to parse
the accepted boundary. Counts describe tool starts, not billing or task completion.

The optional `lastObservation` retains the native discriminated task activity
(kind and timestamp, plus tool name/input character count or retry counters
where required). It remains presentation evidence and never creates a replay
cursor or a completion claim.
