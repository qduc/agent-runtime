# Schema v1 — retained event and interaction contracts

Schema v1 is retained for compatible consumers. Package version and schema
version are different numbers; retaining a parser does not select or enable an
application runtime. See the [migration guide](migration-v1-v2.md) for the
explicit v2 API.

## API and envelope

Root exports `AGENT_EVENT_TYPES`, `FROZEN_AGENT_EVENT_TYPES`, `AgentEventType`,
`AgentEventEnvelope`, `parseAgentEventEnvelope`, its alias `parseEventEnvelope`,
and `AgentWireError` retain their v1 meanings. No unqualified export selects v2.

```ts
import { parseAgentEventEnvelope } from "@qduc/agent-wire";
const event = parseAgentEventEnvelope(
  {
    schemaVersion: 1,
    id: 43,
    sessionId: "session-1",
    type: "turn_completed",
    occurredAt: "2026-10-03T00:00:00Z",
    payload: {},
  },
  "session-1"
);
```

Exactly those six envelope keys are accepted. `id` must be a positive safe
integer. `sessionId` must match `[A-Za-z0-9_-]{1,256}` and the optional expected
Session identity. `occurredAt` is a string of at most128 characters without ASCII
control characters; the v1 parser does not establish ISO validity or provenance.
The payload must be a non-array object. It is not validated by event type.

The authoritative closed event vocabulary remains `AGENT_EVENT_TYPES` in
`src/v1.ts`: session_created; user_message_accepted/rejected; assistant_started;
text_delta/reasoning_delta; tool_started/command_message; approval_required;
interaction_updated/resolved/recovered; usage_update; retry/retry_exhausted;
subagent_started/tool_started/text_turn/command_message/approval_required/
completed/interrupted/question; context_compaction_started/completed/failed;
turn_completed/failed/aborted. The slash lists expand their common prefixes.
There is no aggregate-queue, rotation/reset or multi-change envelope.

The parser rejects unknown keys, unknown types and schemaVersion!=1 with
AgentWireError. It constructs the known envelope while retaining the payload
object; it does not generate IDs/times, persist events, checkpoint a cursor,
reorder data, authenticate, authorize or validate application payloads.

## Transport and compatibility limits

V1 has one numeric ID and one timestamp per event. Applications own the actual
source sequence, durability/replay guarantees and payload schemas. The package
itself never implemented a contiguous-sequence reducer. Some existing browser
consumers require id==last+1 and ignore repeated IDs; those assumptions must not
be mistaken for native Session accepted-sequence semantics.

A producer must not split one accepted boundary into separately numbered v1
frames, repeat one ID for multiple messages, fabricate metadata for live-only
progress, or substitute session_created for a real rotation. The v1 vocabulary
cannot truthfully represent all those direct-engine boundaries. Do not keep an
old engine as a fallback to mask that gap.

For direct-engine migration, the chosen v2 option-B policy keeps raw reasoning
and intermediate tool progress live-only, including after reconnect/crash;
accepted summaries and final results are the recovery surface. V1's historical
reasoning_delta name does not promise durable raw replay or authorize invented
IDs/times for those updates. See the [explicit v2 replay exception](v2.md#explicit-raw-stream-replay-exception-option-b).
This presentation limitation does not authorize removing provider-required
reasoning items/signatures/encrypted metadata or tool calls/results.

Installing0.2.0 does not upgrade a v1 client: its unchanged parser rejects v2.
Use explicit negotiated migration; see [migration](migration-v1-v2.md).

## Independent interaction DTO version1

`PendingInteractionDto`, `validatePendingInteractionDto`, interaction kinds/
variants and `InteractionProtocolError` are unchanged, separately versioned
interaction contracts, not event schema2. They retain strict required/optional
keys, positive revision, existing kind/variant relationships, safe choices and
ask-user shape. Existing string/choice/question bounds remain unchanged in
`src/v1.ts`. The validator does not write answers or make intermediate form
state durable. Reuse this interaction version when compatible; do not pretend
an event-envelope upgrade supplies native partial-answer persistence.
